## 📝 Documentation Rules

### When Adding New Documentation

1. **Add to DEVELOPMENT.md** if it's:
   - A rule or workflow
   - Architecture detail
   - Style guide
   - Build/test process

2. **Add to README.md** if it's:
   - User-facing feature
   - Quick start guide
   - Keyboard shortcuts

3. **Create new reference doc** only if:
   - It's a large, specialized topic (like ON_DEVICE_ARCHITECTURE.md)
   - It's substantial enough to warrant its own file

4. **Don't create** new files for:
   - Small updates (add to existing docs)
   - Historical logs (use existing archive files)
   - Duplicate information

### When Updating Documentation

- **Update DEVELOPMENT.md** if rules/workflows change
- **Update README.md** if user features change
- **Archive old docs** by moving to historical section
- **Don't delete** historical docs (they provide context)
